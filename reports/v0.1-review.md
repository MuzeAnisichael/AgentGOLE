## 2. 做得好的地方

- **范围**：严格守住了 v0.1 范围，没有为后续版本预留占位；`docs/` 未被改动。
- **提交粒度**：一张任务卡一个提交，提交标题清楚，交接基线提交 `d8de003` 可以追溯。
- **安全细节**：
  - 错误信息里的密钥会被脱敏；
  - gole.yaml 中的 `api_key` 只允许写 `${VAR}` 形式的环境变量引用；
  - YAML 解析出错时不回显原文。
- **健壮性细节**：
  - 流式输出中途断线时不重放，避免重复的 token；
  - `<think>` 标签跨分片时也能正确剥离；
  - 并发探测模型能力时，取消一个探测，其他 run 仍可以接手。
- **测试**：55 个测试都针对行为，数量克制，符合测试纪律。
- **报告**：结构完整，证据具体；偏差、评审结果和 multi-agent 记录都有。

## 3. 问题清单（编号转入 v0.2 任务书 P0）

| 编号 | 级别 | 问题 | 位置 | 修复要求 |
| --- | --- | --- | --- | --- |
| R1 | 必须 | prompt 模式下没有注册任何工具，仍强制套用 ReAct 协议。模型不按 `Final Answer:` 格式回答时，会重试 2 次（共 3 次模型调用）、发 error 事件，并且流式输出拿不到任何 token。`lmstudio/`、`vllm/` 和自定义 base_url 默认都走 prompt 模式，L0 对话直接受影响 | `paradigms/auto.py`、`paradigms/react.py` | 没有工具时，auto 和 react 都退化为一次普通的 `CallModel`（不带 marker）后直接 `Finish`。有工具时，如果回复里既没有 `Final Answer:` 也没有 `{`，视为最终回答（去掉开头的 `Thought:` 行），不再重试 |
| R2 | 必须 | 流式模式下，最终回答可能完全没有 token 事件（prompt 模式在等 marker，或重试用尽后以原文结束） | `kernel/engine.py`、`kernel/evaluator.py` | 流式运行中，如果最终回答的文本没有通过 token 事件发出过，就在发 `Finish` 对应的 `step` 之前，补发一个包含完整回答的 token 事件。保证「拼接全部 token == result.text」恒成立 |
| R3 | 必须 | 原生工具调用的参数如果是空字符串或非法 JSON，整次 run 会以「invalid chat completion response」失败；缺少 `id` 的工具调用会得到空 id | `models/wire.py` | 空字符串按 `{}` 处理。非法 JSON 先用共享的 JSON 修复逻辑修复，仍失败时，转成该次调用的工具错误观察（`Error: invalid arguments JSON`）返回给模型，不中断 run。缺少 `id` 时生成一个 |
| R4 | 必须（v0.2 依赖） | 引擎调用 `memory.load(session)` 时没有传入 `query`，长期记忆的检索拿不到当前输入 | `kernel/engine.py` | 改为 `memory.load(session, query=input)` |
| R5 | 建议 | `gole chat` 中单轮出错（例如模型不可达）会直接退出整个 REPL | `cli/__init__.py` | 打印错误后继续下一轮 |
| R6 | 技术债 | 每次模型请求都新建一个 `httpx.AsyncClient`，没有连接复用；调用云端 API 时，每次都多一次 TLS 握手 | `models/client.py` | 本版不处理，记入 DECISIONS，v0.8 处理 |
