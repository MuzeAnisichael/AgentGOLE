### 2.2 本版新增的公共 API

```python
import agentgole as gole

# —— 嵌入模型 ——
emb = gole.Embedding(spec: str, *, base_url=None, api_key=None, batch_size=32, timeout=60.0, retries=2)
emb.embed(texts: list[str]) -> list[list[float]]           # 同步
await emb.aembed(texts) -> list[list[float]]

# —— 记忆（gole.memory 子模块） ——
gole.memory.Window(turns=20)                                # v0.1 已有
gole.memory.Summary(max_tokens=2000, keep_turns=4, model=None)          # model：模型 spec、别名（如 "fast"）或 ModelClient
gole.memory.LongTerm(path="./.gole/memory.db", embedding=None, top_k=5, write="after_run", backend="builtin")   # write: "after_run" | "tool"
gole.memory.Layered(short=..., long=...)
gole.Agent(memory="session" | "summary" | "long" | None | Memory)
agent.memory.add(text, *, session="default")                # 仅 LongTerm / Layered 支持
agent.memory.search(query, *, session="default", k=5) -> list[str]   # 仅 LongTerm / Layered 支持
agent.memory.export(*, session="default") -> dict           # 所有内置记忆都支持
agent.memory.clear(*, session="default")                    # 所有内置记忆都支持

# —— 知识库 ——
kb = gole.Knowledge(
    sources,                       # str | Path | list：文件、目录、glob（如 "./notes/*.md"）或 http(s) URL
    *, embedding=None, store="./.gole/kb", name=None, description=None,
    chunk_size=512, chunk_overlap=64,          # 按字符计
    retriever="hybrid",                        # "vector" | "keyword" | "hybrid"
    rerank=None, backend="builtin",            # 本版只接受这两个默认值，见 §2.3
)
kb.search(query, k=5) -> list[Chunk]; await kb.asearch(...)
kb.add(source); await kb.aadd(source)
kb.ask(question, *, model=None) -> Result
gole.Agent(knowledge=kb | str | Path | list, knowledge_mode="auto")   # "auto" | "tool" | "context"
result.citations -> list[Citation]

# —— 结构化输出 ——
agent.run(input, *, session="default", output: type | None = None) -> Result   # arun / stream / astream 同样增加该参数；见 §3.6
result.output                                               # output 的实例；未指定时为 None
```

CLI 新增：`gole kb build <source...> [--embedding SPEC] [--store DIR] [--name NAME]`。

### 2.3 本版不做

- `Knowledge` 的 `rerank=`、`backend=`，以及 `Knowledge.from_llamaindex`（v0.4）；
- mem0 / Letta 后端（v0.4）；
- 内置工具 `web_search` 等（v0.3）；
- 审批（v0.3）；
- 检查点（v0.5）。

SPEC 中已经出现的参数，本版保留参数名，但只接受默认值：`rerank=None`、`backend="builtin"`（`Knowledge` 和 `LongTerm` 都是）。传入其他值时抛 `ConfigError`，提示「v0.4 起支持」。不写任何占位实现。

## 3. 关键设计约束

### 3.1 类型与协议扩展（P0，Lead）

- 新类型：
  - `Document(text, source, page: int | None, metadata: dict)`；
  - `Chunk(id, text, source, page, score: float)`；
  - `Citation(source, page, text)`，其中 `text` 最多保留 300 字符。
- `Result` 新增 `citations: list[Citation] = []` 和 `output: Any = None`。
- 新协议：
  - `EmbeddingClient`：`name`、`async def embed(texts) -> list[list[float]]`；
  - `Retriever`：`name`、`description`、`async def search(query, k=5) -> list[Chunk]`。
- `Memory` 协议保持不变。另外定义两个可选协议：
  - `ManagedMemory`：`add` / `search` / `export` / `clear`；
  - 绑定钩子 `bind(model: ModelClient, embedding: EmbeddingClient | None)`：Agent 构造时，如果记忆对象有这个方法，就调用一次。
- 事件新增 `retrieve`，字段为 `query` 和 `chunks`（与 SPEC §8.1 一致）。
- `kernel/context.py` 新增 `estimate_tokens(text) -> int`：CJK 字符每个按 1 计，其余字符每 4 个按 1 计。本版所有 token 估算都用它。
- `testing` 新增 `FakeEmbedding(dim=16)`：基于文本哈希生成确定性向量；记录 `calls`，供增量索引的测试断言。
- `pyproject.toml` 首次加入 extras：`rag = ["pypdf", "python-docx", "numpy"]`，`all = ["agentgole[rag]"]`。核心依赖不变。

### 3.2 嵌入模型（`models/embedding.py`）

- 请求：`POST {base}/embeddings`，body 为 `{"model": ..., "input": [...]}`。按 `batch_size` 分批；重试和错误脱敏复用聊天客户端的实现。
- provider 与 v0.1 的路由表一致。`deepseek/` 不提供嵌入接口，遇到时抛 `ConfigError`，提示改用其他 provider。
- 默认嵌入模型的解析顺序：显式参数 → gole.yaml 中 `models.embed` 别名 → 环境变量 `GOLE_EMBEDDING` → 抛 `ConfigError`，提示配置方法。

### 3.3 记忆（`memory/`）

- 引擎改为调用 `memory.load(session, query=input)`（R4）。
- **`Summary`**：
  - 按 session 保存在进程内。
  - `load` 返回：一条系统消息形式的摘要（如果有）+ 最近 `keep_turns` 轮原文。
  - `save` 时，如果「摘要 + 原文」的估算 token 数超过 `max_tokens`，就调用一次模型，把较早的轮次压缩进摘要。
  - 模型取 `model` 参数；未提供时，用 `bind` 传入的 Agent 模型。
  - 压缩失败时，保留原文不压缩，记 warning 日志，不中断 run。
  - token 估算用 T1 提供的 `estimate_tokens`。
- **`LongTerm`**（内置 SQLite）：
  - 存储：`facts` 表（`session`、`text`、`embedding`、`created_at`），开启 WAL。
  - `write="after_run"`：`save` 后调用一次模型，从本轮对话中抽取不超过 5 条持久事实，模型以 JSON 字符串数组返回，用共享的修复逻辑解析；文本规范化后去重。
  - `write="tool"`：通过 `tools()` 方法提供 `remember(fact)` 和 `recall(query)` 两个工具，Agent 自动注册。
  - `load(session, query)`：有嵌入模型时，按余弦相似度取 `top_k`；没有时，用与知识库相同的 BM25 分词器取 `top_k`。结果作为一条系统消息返回，格式为「已知信息：\n- …」。
- **记忆内部的模型调用**：
  - 发生在 `memory.save` 中，也就是最终 token 已经发出之后、`run_end` 之前。SPEC 所说的「异步抽取」指的是不阻塞流式输出。run 返回前抽取已完成，因此进程退出时数据已经落盘（B4 依赖这一点）。
  - 不计入 `result.usage` 和 `max_steps`，但受 run 的 `timeout` 约束。
- **预设**：
  - `memory="summary"` = `Summary()`；
  - `memory="long"` = `Layered(short=Summary(), long=LongTerm())`。
  - `Layered.load` 先返回长期记忆的结果，再返回短期记忆的结果；`save` 同时写两边。

### 3.4 知识库（`knowledge/`）

- **加载器**（`knowledge/loaders.py`，输出 `Document` 列表）：
  - `.md`、`.markdown`、`.txt`：UTF-8 读取，非法字节替换。
  - http(s) URL：用 httpx GET；`text/html` 内容用标准库 `html.parser` 提取可见文本，跳过 script 和 style。
  - `.pdf`（pypdf，带页码）和 `.docx`（python-docx）：需要 `[rag]` extra。未安装时抛 `MissingDependencyError`，提示 `pip install "agentgole[rag]"`。
  - 目录递归读取；支持 glob；不支持的扩展名跳过，并记 warning。
- **切分**（`knowledge/chunking.py`）：
  - 单位是字符。
  - 先按 Markdown 标题和空行切段，再按句末标点（`。！？.!?` 和换行）切句；在 `chunk_size` 以内打包，相邻块重叠 `chunk_overlap` 字符。
  - 保留来源和页码。
- **存储**（`knowledge/store.py`）：
  - `name` 默认取第一个来源的目录名、文件名主干或 URL 主机名，规范化为 `[a-z0-9_]`；取不到时用 `kb`。
  - `description` 默认为「在知识库 <name> 中检索，来源：<前 3 个来源>」。
  - 位置：SQLite 文件 `{store}/{name}-{h}.db`，其中 `h` 是 sources 规范化后哈希的前 8 位，用于区分同名的不同目录。
  - 表结构：
    - `documents`（`source`、`sha256`、`page_count`）；
    - `chunks`（`id`、`source`、`page`、`text`、`embedding`：L2 归一化后的 float32，以 `array('f')` 序列化）；
    - `meta`（嵌入模型名、维度）。
- **增量索引**：
  - 按文件内容的 sha256 判断：未变化的文件跳过；变化的文件先删除旧块，再重新嵌入；源目录中已删除的文件，同步删除对应的块。
  - 嵌入模型名或维度变化时，全量重建，并记 warning。
- **检索**（`knowledge/retrieval.py`）：
  - 关键词：BM25（k1=1.5，b=0.75），首次检索时在内存中建索引。分词规则：拉丁字母和数字按词切分并转小写；CJK 字符切成二元组，单个汉字保留为一元。
  - 向量：已安装 numpy 时用 numpy，否则用纯 Python 点积。numpy 必须在函数内部延迟导入（B9）。
  - 混合：两路各取 `k*4` 个结果，用 RRF（k=60）融合。
- **`kb.ask`**：等价于 `Agent(model, knowledge=kb, knowledge_mode="context").run(question)`；模型默认取默认模型。

### 3.5 Agent 接入知识库（P2，Lead）

- `knowledge=` 接受 `Knowledge`、路径字符串或 `Path`（自动构造 `Knowledge`），也可以是由它们组成的列表。
- `knowledge_mode`：
  - `"tool"`：每个知识库注册为一个工具 `search_<name>`，描述取 `kb.description`，返回带编号的结果，格式为 `[1] (source p.3) text`。同一个 Agent 上出现重名知识库时，抛 `ConfigError`，提示设置 `name`。
  - `"context"`：每次 run 的第一次 `CallModel` 之前，以 `query=input` 检索 `k=5`，作为一条系统消息「参考资料：」注入，条目带编号。
  - `"auto"`：解析后的 `tool_mode == "native"` 时用 `tool`，否则用 `context`。
- 每次检索都发 `retrieve` 事件。`result.citations` 按出现顺序收集本次 run 检索到的块，并按块 id 去重。
- 注入逻辑放在 `kernel/context.py`，不要写进范式。

### 3.6 结构化输出（P2，Lead）

- `output` 接受 pydantic `TypeAdapter` 能处理的任何类型。`BaseModel` 子类是主要用法，`list[str]` 这类类型也要支持，因为 SPEC §7 的自定义范式示例会用到。校验和 schema 都通过 `TypeAdapter` 实现，封装在共享模块 `_json.py` 中，供 v0.5 的 `model.generate(output=...)` 复用。
- 指定 `output` 后，在系统提示末尾追加「最终回答只输出一个符合以下 JSON Schema 的 JSON 值」和 schema。
- 最终回答先用共享的修复逻辑解析，再用 `TypeAdapter.validate_python` 校验。失败时，追加一条说明错误的 user 消息，让模型重答，最多 2 次，计入 `max_steps`。仍失败时，抛新增的 `OutputValidationError`（继承 `AgentGoleError`）。
- 成功时，`result.output` 是该类型的实例，`result.text` 是原始 JSON 文本。
- 校验放在引擎处理 `Finish` 的位置，与范式无关。原生和 prompt 两种模式行为一致。

### 3.7 CLI

`gole kb build`：按 gole.yaml 和参数构造 `Knowledge`，然后建索引，输出文件数、新增/跳过/删除的块数和耗时。
