## 3. 关键设计约束

### 3.1 公共类型（`protocols/types.py`，pydantic v2）

- `Message`：`role`（`"system"` | `"user"` | `"assistant"` | `"tool"`）、`content: str | None`、`tool_calls: list[ToolCall] = []`、`tool_call_id: str | None`、`name: str | None`、`reasoning: str | None`（见 §3.5）
- `ToolCall`：`id`、`name`、`arguments: dict[str, Any]`
- `ToolSpec`：`name`、`description`、`parameters`（JSON Schema 字典）
- `ToolResult`：`call_id`、`name`、`output: str`、`error: str | None`
- `Usage`：`prompt_tokens`、`completion_tokens`、`total_tokens`；支持相加
- `Capabilities`：`tools: bool`、`json_mode: bool`、`vision: bool`、`context: int | None`
- `ModelResponse`：`message: Message`、`usage: Usage`、`model: str`、`raw: Any = None`
- `Event`：`type`、`run_id`、`ts`、`step: int | None`。设置 `model_config = ConfigDict(extra="allow")`，各事件特有的字段作为额外字段，字段名严格按 SPEC §8.1 表格（例如 `ev.text`、`ev.tool`、`ev.args`、`ev.output`、`ev.error`）。v0.1 需要发出的事件：`run_start`、`run_end`、`memory_load`、`memory_save`、`model_start`、`token`、`model_end`、`tool_call`、`tool_result`、`step`、`error`。
- `Step`：一次 Action 及其结果的记录。`Result.steps` 和 `RunState.history` 都是 `list[Step]`。
- `Result`：`text`、`steps`、`usage`、`trace`、`run_id`、`session`。

### 3.2 协议（`protocols/`）

```python
class ModelClient(Protocol):
    name: str
    async def generate(self, messages: list[Message], *, tools: list[ToolSpec] | None = None, **params) -> ModelResponse: ...
    def stream(self, messages: list[Message], *, tools: list[ToolSpec] | None = None, **params) -> AsyncIterator[ModelChunk]: ...
    async def probe(self) -> Capabilities: ...

class Tool(Protocol):
    spec: ToolSpec
    async def call(self, **arguments: Any) -> Any: ...

class Memory(Protocol):
    async def load(self, session: str, query: str | None = None) -> list[Message]: ...
    async def save(self, session: str, messages: list[Message]) -> None: ...

class Paradigm(Protocol):
    async def step(self, state: RunState, ctx: StepContext) -> Action: ...
```

- `ModelClient` 是内部的异步协议；`gole.Model` 是面向用户的包装，提供同步的 `generate()` 和异步的 `agenerate()`。SPEC §6.1 和 §8.3 的两种写法因此都成立。
- `RunState`：`input`、`messages`（本次 run 发给模型的完整消息列表）、`turn`（已执行的 Action 数）、`scratch: dict`、`history: list[Step]`、`last_response: Message | None`。
- `StepContext`：`model: ModelClient`、`tools: dict[str, Tool]`、`tool_mode: "native" | "prompt"`（已解析好的结果）、`run_id`。
- Action（v0.1 只有三种）：
  - `CallModel(messages=None, use_tools=True, emit_tokens_after=None)`：`messages=None` 表示使用 `state.messages`。
  - `CallTool(calls: list[ToolCall], as_observation=False)`。
  - `Finish(output: str)`。

### 3.3 运行循环（`kernel/engine.py`）

1. 发出 `run_start`；`memory.load(session)` → `memory_load`；组装消息：system（instructions）+ 记忆 + 本次 user 输入。
2. 循环调用 `paradigm.step()`，由引擎执行返回的 Action：
   - `CallModel`：先发 `model_start`；流式模式下发 `token` 事件；结束时发 `model_end`（带 `usage`）；把回复追加进 `state.messages`。
   - `CallTool`：每次调用先发 `tool_call`，执行后发 `tool_result`。默认以 `role="tool"` 消息追加结果；`as_observation=True` 时，改为合并成一条 `role="user"` 的 `Observation:` 消息（供提示词模式使用）。
   - `Finish`：结束循环。
   - 每个 Action 执行完都发一次 `step`。
3. Action 数超过 `max_steps` → 抛出 `MaxStepsError`（同时发 `error` 事件）。整次 run 超过 `timeout` → 抛出 `RunTimeoutError`。
4. 结束时 `memory.save(session, [user 消息, 最终 assistant 消息])` → `memory_save`；发 `run_end`；返回 `Result`。
5. `token` 事件：原生工具调用模式下，转发回复内容的全部增量（工具调用参数的增量不发）。`CallModel` 带 `emit_tokens_after` 标记时，先缓冲，标记出现后才开始转发标记之后的文本；标记始终没有出现，就不发 `token`。
6. 事件回调里抛出的异常只记日志，不中断这次 run。

### 3.4 工具调用路径（`tools/`）

- `@gole.tool`：用函数签名生成 pydantic 模型，再导出 JSON Schema。参数说明从 docstring 中解析，支持 Google 风格的 `Args:` 小节，也支持 SPEC 示例里的 `name: 说明` 行格式。
- 执行顺序：校验参数 → 带超时调用（默认 30 秒）→ 序列化结果。字符串原样返回；dict、list 和 pydantic 模型转成 JSON；其他类型用 `str()`。结果超过 8000 字符时截断，并加上 `...[truncated]`。
- 工具抛出的异常不中断 run：转成 `ToolResult.error`，返回给模型的内容是 `Error: {类型}: {信息}`。调用了不存在的工具，也按同样方式返回。
- 内置工具：
  - `calculator`：基于 `ast` 的安全求值，只允许数字、`+ - * / // % **`、括号、一元负号，以及 `math` 模块中的 `sqrt sin cos tan log exp pi e`；`**` 的指数绝对值超过 1000 时拒绝。
  - `datetime`：返回当前日期、时间和星期；可选参数 `timezone`（IANA 名称）和 `offset_days`。

### 3.5 模型适配（`models/`）

| 前缀 | 默认 base_url | 密钥 | 能力探测 |
| --- | --- | --- | --- |
| `ollama/` | `http://localhost:11434/v1` | 无 | `POST {host}/api/show {"model": name}`，返回的 `capabilities` 中含 `"tools"` 即视为支持；请求失败或缺少该字段时，视为不支持 |
| `openai/` | `https://api.openai.com/v1` | `OPENAI_API_KEY` | 视为支持工具调用 |
| `deepseek/` | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` | 视为支持工具调用 |
| `dashscope/` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `DASHSCOPE_API_KEY` | 视为支持工具调用 |
| `lmstudio/` | `http://localhost:1234/v1` | 无 | 视为不支持 |
| `vllm/` | 必须提供 base_url（参数或 gole.yaml 中的 `providers.vllm.base_url`） | 可选 | 视为不支持 |
| 不带前缀 + `base_url` | 用户提供 | 可选 | 视为不支持 |
| 不带前缀、也没有 `base_url` | 在 gole.yaml 的 `models` 中查别名 | — | — |
| `anthropic/` 及其他前缀 | — | — | 抛出 `ConfigError`，提示该 provider 暂不支持 |

- 所有 provider 都走同一个 OpenAI 兼容客户端（httpx.AsyncClient）：`POST {base}/chat/completions`，支持非流式和 SSE 流式；流式时按 `index` 累积 `tool_calls` 的增量。
- 遇到 429、5xx 或连接错误时，按 `retries` 做指数退避重试（基数 0.5 秒，若有 `Retry-After` 则遵守）。错误统一抛 `ModelError`，信息里包含 provider、HTTP 状态码和返回的错误摘要，**不得包含密钥**。
- 推理内容：回复内容以 `<think>…</think>` 开头时（qwen3 等模型常见），把这段内容剥离出来，放进 `Message.reasoning`，不计入回答文本。
- `tool_mode` 的解析顺序：Agent 参数 → Model 参数 → `"auto"` 时调用 `probe()`。探测结果按 `Model` 实例缓存。原生模式下，如果服务端返回 400 且错误信息表明不支持 tools，则把这个 Model 实例降级为 prompt 模式，发一个 `error` 事件（`recoverable=True`），然后重试本次调用。

### 3.6 范式（`paradigms/`）

- `auto`：`tool_mode == "native"` 时，执行「调用模型 → 有 `tool_calls` 就执行工具 → 再调用模型」的循环，直到回复不含工具调用，然后 `Finish`。`tool_mode == "prompt"` 时，整次 run 交给 `react`。
- `react`（降级第一阶段）：在 system prompt 末尾追加工具说明（名称、描述、参数 Schema）和输出协议：

  ````text
  Thought: <简短思考>
  Action:
  ```json
  {"tool": "<工具名>", "arguments": {...}}
  ```
  ````

  或者：

  ```text
  Thought: <简短思考>
  Final Answer: <最终回答>
  ```

  - 解析规则：出现 `Final Answer:` 就以其后的文本 `Finish`；否则取第一个 JSON 对象（带围栏或不带均可）。
  - 修复：尾随逗号、单引号、未闭合的围栏。
  - 校验：工具名必须存在，参数必须通过 Schema 校验。
  - 解析或校验失败时，追加一条 user 消息说明错误、要求按格式重答，最多重试 2 次；仍然失败，就把原始文本作为答案 `Finish`，并发 `error` 事件（`recoverable=True`）。
  - 调用模型时使用 `CallModel(use_tools=False, emit_tokens_after="Final Answer:")` 和 `CallTool(as_observation=True)`。

### 3.7 记忆、配置、同步包装、轨迹

- **记忆**：`memory/window.py` 中的 `Window(turns=20)`：进程内按 session 保存，一轮 = user 消息 + 最终 assistant 消息，保留最近 20 轮；`memory="session"` 对应 `Window()`。不做持久化。
- **配置**：
  - 查找顺序：环境变量 `GOLE_CONFIG` 指定的路径 → `./gole.yaml` → `~/.gole/gole.yaml`。
  - 支持 `default_model`、`models`（别名）、`providers.<name>.base_url / api_key`，值中可以用 `${VAR}` 引用环境变量。
  - `engine: native` 静默接受；其他未知的顶层键给出 warning，但不报错。
  - 找不到配置文件不是错误；只有需要模型却解析不出来时，才抛 `ConfigError`，并提示设置 `GOLE_MODEL` 或运行 `gole init`。
- **同步包装**（`_sync.py`）：
  - 当前线程没有正在运行的事件循环时，直接 `asyncio.run`；
  - 有正在运行的循环时（如 Jupyter），把协程交给一个复用的后台线程事件循环执行，阻塞等待结果；
  - `stream()` 用后台线程 + 队列，把异步生成器转成同步迭代器。
- **轨迹**：
  - `result.trace.show()` 按 SPEC §9.1 的格式打印步骤树（纯文本，不引入 rich 等依赖）；
  - `verbose=True` 时，在运行过程中把同样格式的行实时打印到 stderr。
- **CLI**（入口 `gole = "agentgole.cli:main"`，用标准库 argparse）：
  - `init`：生成 SPEC §3.2 中的 gole.yaml 模板和 `agent_example.py`；文件已存在时拒绝覆盖，除非加 `--force`。
  - `doctor`：逐个检查配置中的模型，输出格式与 SPEC §3.3 一致。
  - `chat`：REPL；`target` 的格式为 `path/to/file.py:attr`；支持 `/exit`、`/reset`；回答流式输出。
  - CLI 文案集中放在 `cli/messages.py`，与 SPEC 示例一样用中文。
- **错误层级**（`errors.py`）：`AgentGoleError` ← `ConfigError`、`ModelError`、`ToolError`、`MaxStepsError`、`RunTimeoutError`、`MissingDependencyError`。
- **`FakeModel`**（`agentgole.testing`）：
  - 签名：`FakeModel(script, *, tools_supported=True, name="fake")`。
  - `script` 的每一项对应一次模型调用：字符串表示文本回复；`fake_tool_call(name, args)` 或它的列表表示带 `tool_calls` 的回复。
  - 流式调用时，把文本切成若干段依次返回。
  - `fm.requests` 记录每次收到的 `messages` 和 `tools`，供断言使用。
  - 脚本用尽后再被调用，抛 `AssertionError`。
- **公共导出**：`__all__ = ["Agent", "Model", "Result", "Event", "tool", "__version__"]`。
