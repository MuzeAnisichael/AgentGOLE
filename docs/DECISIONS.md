## 设计阶段（2026-11-11 至 11-12）

| 编号 | 决策 | 理由 | 来源 |
| --- | --- | --- | --- |
| D-001 | 支持三种运行模式：A 原生内核、B 内核 + 框架组件、C 框架托管，由用户自由选择 | 兼顾零依赖上手和复用现有框架资产 | SPEC §2.2 |
| D-002 | 原生内核以 NanoHarness 的六关注点结构为骨架，运行时的安全与恢复机制参考 Minimal Local Agent | 接口与组件一一对应，且不绑定编码场景 | SPEC §2.3 |

| D-004 | 内置实现做到「单机可用」，生产级能力交给模式 B / C 的后端 | 避免重复造轮子，又保证模式 A 能用于真实项目 | SPEC §12 #5 |
| D-005 | 本地模型的工具调用降级分阶段建设：v0.1 做基础兼容，v0.3 做约束解码和基准测试 | 先保证能用，再用数据决定投入 | SPEC §12 #6 |
| D-006 | 提供 YAML 声明式定义，但代码优先 | — | SPEC §12 #7 |
| D-007 | 项目名暂定 AgentGOLE；PyPI 包名 `agentgole`，惯用导入 `import agentgole as gole`，命令行 `gole` | — | SPEC §12 #8 |
| D-008 | 首发只支持 Python ≥ 3.11，许可证 Apache-2.0 | 3.10 已停止维护 | SPEC §12 #9、#10 |
| D-009 | 核心运行时依赖只有 httpx、pydantic、pyyaml；其他能力一律通过 extras 安装 | 「3 行代码」体验和轻量安装 | SPEC §1.4 |

## v0.1（审核：2026-11-18）

| 编号 | 决策 | 理由 | 来源 |
| --- | --- | --- | --- |
| D-101 | `examples/quickstart.py` 比 3 行多一行 `getenv`，README 保留 3 行写法 | 同一份示例可以在两个 provider 上分别验收 | v0.1 报告 §4 |
| D-102 | 非函数类的外部 Tool，只支持常用的 JSON Schema 约束子集；遇到不支持的约束时明确报错 | 不增加 jsonschema 依赖 | v0.1 报告 §4 |
| D-103 | 工具输出的 8000 字符上限包含截断标记；`run_end` 事件里内嵌的结果，其轨迹截止到前一个事件 | 保证总长度不超限；避免结果引用自身 | v0.1 报告 §4 |
| D-104 | 能力探测的耗时计入整次 run 的 timeout；首次探测被取消后，其他 run 可以接手 | 探测本身也是本次运行的 I/O | v0.1 报告 §4 |
| D-105 | `gole doctor` 对每个模型发起一次 `max_tokens=1` 的真实请求 | 端口能连通不代表指定的模型可以调用；云端会产生极少量费用 | v0.1 报告 §4 |
| D-106 | Windows 上缺少 IANA 时区数据时，`datetime` 工具改用系统 ICU | 不增加 tzdata 依赖 | v0.1 报告 §4 |
| D-107 | ruff 的检查范围限定为 Python 工程文件 | `docs/` 只读，不应被格式化 | v0.1 报告 §4 |
| D-108 | 每次模型请求新建一个 httpx 客户端（没有连接复用），作为技术债保留，v0.8 处理 | 实现简单，且避免跨事件循环共享连接池 | v0.1 审核 R6 |
| D-109 | 没有注册工具时不使用 ReAct 协议；带工具时，没有动作对象的回复视为最终回答 | 避免无意义的重试，保证流式输出 | v0.1 审核 R1 |
